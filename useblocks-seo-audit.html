01 · SUMMARY

Сводный отчёт

Дата: 2026-09-01 Скоуп: технический SEO + конкуренты/gap + контент/семантика. US-рынок, английский язык. Продукт: Blocks — AI-powered no-code email builder (206 шаблонов, экспорт под 53 платформы, embeddable-плагин).

Топ-5 критичных проблем

  1. Заголовочная структура убита билдером — на главной нет H1, на страницах сравнений нет ни H1, ни H2 (11 тыс. знаков текста вёрстаются дивами). Страницы структурно невидимы для Google и LLM (см. tech-seo-audit.md §4–5).
  2. Контентного контура нет вообще: 0 статей блога (у всех 6 конкурентов — от 63 до 937), /blog/ занят лендингом, хаб /comparisons/ пуст, глоссария нет (см. gap-analysis.md §3–4).
  3. 53 платформенные страницы — мёртвый BOFU-актив: конкуренты ранжируются идентичными галереями, Blocks в SERP по «free mailchimp email templates» отсутствует — тонкий шаблонный текст без H2 (см. gap-analysis.md §4.2, content-audit.md §4.1).
  4. Тестовый мусор в проде: /test77/, /test-2/ — 200, index,follow, в sitemap; там же просроченный /blackfriday2024/ (см. tech-seo-audit.md §2).
  5. Аналитическая слепота: CrUX пустой (трафика мало), доступа к GSC нет — ни позиций, ни показов, ни покрытия индекса; keys.so для US-рынка неприменим (см. tech-seo-audit.md §3, gap-analysis.md §1).

Что НЕ вошло в аудит (и почему)

  • Классический gap-анализ по keys.so — API покрывает только Яндекс/Рунет, для US-сайта данные нерелевантны (профиль снят для справки: 1 ключ в топ-10 Яндекса). Заменён структурным анализом sitemap 6 конкурентов + SERP-чеками.
  • Частотности US-запросов — нет доступа к Ahrefs/Semrush; семантика размечена качественными сигналами (SERP-конкуренция, саджесты). После подключения GSC — уточнить фактическими показами.
  • Позиции и трафик — нет GSC-доступа, CrUX пустой.
  • UX/конверсионный аудит и аудит самого приложения — за скоупом SEO-аудита.
  • Бэклинки — инструментов под US-профиль нет в наборе.

Следующие шаги

  5. Через 2–3 месяца — пересбор приоритетов по данным GSC, решение по блогу и глоссарию (пп. 8, 10).
  6. Оформить план работ: useblocks/plans/growth-plan.md (по договорённости).

4. Кластеры gap

4.1. 🔴 Блог / контент-хаб — «how to», гайды по email-маркетингу

  • Есть у 6 из 6 конкурентов (63–937 статей).
  • Интент: информационный (TOFU) → прогрев на билдер.
  • У useblocks /blog/ занят лендингом, статей 0.
  • Вердикт: брать — это основной канал органики всей ниши.

4.2. 🔴 Платформенные страницы «email templates for » — уже есть, но не работают

  • У useblocks 53 страницы, у конкурентов аналог ранжируется (unlayer/beefree/designmodo в топе по «free mailchimp email templates»).
  • Причина отставания видна из техаудита: тонкий шаблонный текст, 0 H2, одинаковая структура на всех 53.
  • Интент: коммерческий (BOFU) — человек уже выбрал ESP и ищет шаблоны.
  • Вердикт: брать в первую очередь — актив создан, его надо дожать, не строить с нуля.

4.3. 🟠 Сравнения и альтернативы («stripo alternatives», «beefree vs unlayer», «X vs Y»)

  • Есть у chamaileon (9) и topol (7); классический BOFU-перехват чужого брендового спроса.
  • У useblocks одна страница-сирота без H1/H2 и пустой хаб.
  • Вердикт: брать — дешёвый BOFU, малые конкуренты доказали достижимость.

4.4. 🟠 Глоссарий email-маркетинга (programmatic)

  • stripo — 149 терминов, topol — 194. Дёшев в производстве, собирает длинный хвост определений, кормит LLM-цитируемость.
  • Вердикт: брать вторым эшелоном — трафик информационный, но термины ниши конвертируются в знание бренда.

4.5. 🟠 Масштаб библиотеки шаблонов

  • 206 карточек против 1 300–2 000. Каждая карточка у конкурентов — посадочная под «<занятие/повод> email template».
  • Вердикт: брать выборочно — не гнаться за 1 500, а закрыть высокочастотные типы, которых нет (по type-таксономии видно дыры: Follow Up — 0 шаблонов при существующей категории).

4.6. 🟡 Интеграционные лендинги (« integration»)

  • stripo 95, topol 26, beefree 15. Отличаются от шаблонных страниц интентом «как подключить».
  • Вердикт: возможно позже — сначала дожать шаблонные страницы тех же платформ.

4.7. 🟡 AI-угол: «ai email template generator» и родственные

  • SERP слабый: Venngage, GMass и мелкие тулзы — гигантов нет. Blocks позиционируется как AI-билдер, но под AI-запросы нет ни одной выделенной страницы.
  • Вердикт: брать — редкий случай свободной поляны под собственное позиционирование.

4.8. ⚪ Use-cases, вебинары, web stories

  • Есть у части конкурентов. Требуют продакшена, эффект косвенный.
  • Вердикт: не брать сейчас.

5. Приоритетные направления (топ-3)

  1. Дожать 53 платформенные страницы (кластер 4.2): уникальный контент на топ-10 платформ (Mailchimp, Klaviyo, HubSpot, Shopify, SendGrid…), H2-структура, FAQ, счётчики шаблонов, взаимные ссылки с карточками. Impact: high (BOFU, актив готов), Effort: med.
  2. Кластер сравнений/альтернатив (4.3): починить хаб /comparisons/, 10–15 страниц «<конкурент> alternatives» и «X vs Y» с нормальной структурой заголовков. Impact: high (перехват брендового спроса, низкая конкуренция), Effort: med.
  3. Запустить блог + AI-страницы (4.1 + 4.7): вернуть /blog/ под контент-хаб, первые 10–15 статей вокруг шаблонных тем и AI-генерации писем; отдельная посадочная под «AI email template generator». Impact: med-high (долгий, но обязательный канал), Effort: high.

6. Что НЕ брать и почему

  • Гонка объёма шаблонов до уровня unlayer (2 000) — производственная задача без гарантии SEO-отдачи; сначала выжать существующие 206.
  • Вебинары/видео/web stories (stripo) — контентный продакшен другого порядка, у stripo это работает на удержание, не на органику.
  • Embeddable SDK-направление (unlayer, chamaileon) — отдельная продуктовая стратегия, не SEO-решение.
  • Рунет/Яндекс — продукт не локализован под RU, keys.so-видимость 0 закономерна, вкладываться нет смысла.

Паттерн: SERP слабый — Venngage (генератор-тулза), GMass (блог-пост), attherate/dfirst/emailcanvas (микро-тулзы). Ни один из 6 прямых конкурентов не занял. Формат победителя: интерактивная страница-генератор + пояснительный текст. У Blocks фича в продукте есть — нужна публичная страница-витрина.

4.3. Alternatives: «stripo alternatives»

Паттерн: микс — G2/OMR (агрегаторы, их не подвинуть) + собственные страницы конкурентов (designmodo/postcards/stripo/, mailmodo/comparison/, maileditor блог). Свои страницы в этом SERP живут → страница «Stripo alternatives: Blocks + ещё 5» достижима.

4.4. Шаблоны generic: «free html email templates»

Паттерн: в топе галереи гигантов с числом в title («1650+ free…», «1280+…») + подборки. С 206 шаблонами соревноваться числом нельзя — заходить через хвосты (типы/сезоны/индустрии) и качество превью.

4.5. Embed/SDK: «embeddable email editor sdk»

Паттерн: Beefree SDK (developers.beefree.io), Unlayer, Chamaileon SDK + ранжирующиеся малые (maillayers.com, dragble.com, easyemail.pro). Формат: продуктовый лендинг для разработчиков с demo, доками и pricing. Ниша сложная, но малые игроки в топе доказывают достижимость.

6. Выводы

Топ-3 точки роста: 1. 53 платформенные страницы — готовый BOFU-актив, который не работает. Конкуренты ранжируются идентичным форматом; нужен контент, не новая архитектура. 2. Две свободные поляны под собственное позиционирование: AI-generator SERP без гигантов + embeddable-продукт /plugin/, невидимый из-за пустого title. Оба — быстрые победы. 3. Контентная машина с нуля: блог + сравнения + глоссарий — то, что есть у всех 6 конкурентов и полностью отсутствует у Blocks.

Риски и ограничения: - Нет данных о частотностях US — приоритеты выставлены по SERP-сигналам; после подключения GSC пересмотреть через 2–3 месяца по фактическим показам. - Вёрстка билдера кладёт заголовки дивами (см. техаудит) — без решения этой проблемы новые страницы унаследуют структурную слепоту. - Библиотека в 206 шаблонов против 1300–2000 у лидеров — числом в title играть нельзя, только хвостами и качеством. - Сезонный кластер требует календарной дисциплины (готовить за 6–8 недель).
